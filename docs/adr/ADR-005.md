# ADR-005: Make Blender the single source for visuals and colliders; GLBs are client-only
**Date:** 2026-10-08 **Status:** proposed
### Context
Phase 2 replaces three.js-drawn debug boxes with Blender models loaded as GLBs. Collision data currently lives as hand-typed numbers in both ```Level.cs``` and ```level.js```, and traps will add a third consumer, the Bepu world. Hand-syncing three copies against a model that artists keep editing would guarantee walls you can see but walk through.

### Decision
Author the level in Blender with simple box and sphere objects named ```collider_*```. A build step exports the visual GLB for three.js and generates the collider data for ```Level.cs```, ```level.js```, and the Bepu static world from those objects. The server reads only the generated numbers and never parses a GLB.

### Consequences
Moving a wall in Blender updates every collision world at once. That removes the hand-synced data in ADR-002's mirror, although the movement logic is still mirrored. The server stays free of a glTF parser and ships no art. The build step becomes a required part of editing a level, and forgetting to run it reintroduces drift, so CI should fail when the generated files are stale. I rejected having the server parse the GLB (it adds a dependency and couples gameplay to art files) and mesh colliders (too expensive, and impossible to mirror in the kinematic controller).
