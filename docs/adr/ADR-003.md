# ADR-003: Hold matches in an in-memory RoomRegistry instead of one global world
**Date:** 2026-09-30 **Status:** accepted
### Context
The first build had a single global world, so every connection joined the same match and a win was never reset. The planned fix was global reset. What the game actually needs is many isolated 2-4 player matches running concurrently and live 20Hz state doesn't belong in a database.

### Decision
A singleton RoomRegistry holds a Room per match code in memory, and the GameLoop ticks every active room. Each broadcast is scoped to that room's SignalR group. Rooms are created instantly and torn down when empty, which replaces the global reset entirely. 

### Consequences
Many matches can run on one server, and each starts clean, so the bug where the win persists disappears through this design. All rooms die iwth the process, which means a deploy kicks each players. One issue that remains but is extremely rare, a race bug where a player can possibly join a room while it is being torn down (issue is deferred). This decision can be revisited if the game requires more than one server, which would mean it requires routing each room code to a single server.
